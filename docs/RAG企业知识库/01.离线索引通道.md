
## 一、多种格式文档解析

>设计一个 DocumentParser 接口，方便扩展后续多种格式，以下四种格式都是当前接口的实现

PDF 解析过程
```
读取 PDF
→ PDFBox 打开文档
→ 按页提取文本
→ 清理空格和换行
→ 识别页面开头的章节标题
→ 保存页码、正文和章节标题
→ 从第一页提取文档标题
→ 返回 ParseResult
```
DOCX 解析过程
```
读取 DOCX
→ 按文档顺序遍历段落和表格
→ 根据 Heading/标题样式识别章节标题
→ 遇到新标题时保存上一节
→ 将表格转换成文本并归入当前章节
→ 保存最后一节
→ 从文档属性读取文档标题
→ 返回 ParseResult
```
MD当前解析流程
```
读取 Markdown 文件
→ 按行遍历
→ 识别代码块范围
→ 识别一级、二级标题
→ 根据标题和长度切分章节
→ 去除 Markdown 语法
→ 每个章节构造一个 PageContent
→ 返回 ParseResult
```
TXT
```
读取全部字节
→ 尝试 UTF-8 解码
→ 乱码较多时改用 GBK
→ 删除 BOM (隐藏字符)
→ 统一换行符
→ 检查空文本
→ 检查是否疑似二进制文件
→ 整个文件作为一个 PageContent
```

>解析结果 ParseResult，含有逻辑页面、页数、文档标题，是否成功，错误信息


## 二、分块策略

针对不同的文档情况，采用不同的策略
##### 1. 固定窗口滑动分块

>这个策略的核心思想是：按照固定长度切分文本，并保留一定的重叠内容，同时尽量选择自然语言边界作为切分位置

chunkSize = 512； chunkOverlap = 64

对每一个逻辑页面进行处理
设定 start 和 end 划定 chunkSize 范围
如果end 处不是句子边界，就要向前找到一个好的断点（段落 > 句号 > 逗号 > 空格），要设定一个回退下限 = 100 个字符
将范围中的内容保存
下一个start = end - chunkOverlap，如果end 已经到达为文档末尾，就不再回退
将内容 text 封装为 chunk，含有 token估算、原页面号、章节标题等
##### 2. 结构感知分块（跨页）

>这个策略的核心思想是：按顺序读取每个逻辑页面，把没有遇到新标题的页面内容持续追加到同一个 current 缓冲区；只有遇到下一个标题时，才认为上一章节结束，并使用保存的章节标题、起始页和累计正文生成一个 TextSection

维护三个量：当前标题，当前页码，当前正文
对每一个逻辑页面进行处理
逐行判断页面中的每一行
如果是普通段落，将段落追加到正文中
如果是标题，且正文size > 50，就直接将内容 current 封装为一个 TextSection
上一页没有结束的章节，其正文继续追加到下一页的 current 中

处理完得到一个章节List
然后对每一节大小判断
如果小于 chunksize，就直接作为一个chunk
==如果大于 chunksize，对该节内容单独作为ParseResult，降级到固定窗口划分==

## 三、Embeding

传入 String 文本text List 批量向量化
先查询 Redis，将命中的块和未命中的块分开保存

对于未命中的块 List ，调用 API，API有单次请求限制（项目设置为10）
用 start 和 end 来控制每次处理 List 的元素，传入batch调用 API
```java
embeddingModel.call(new EmbeddingRequest(batch, null));
```
API调用返回 EmbeddingResponse ，response 可以统计 token 消耗，并且提取向量 float 数组保存到 result 中

>调Embedding API 遇到网络问题，指数退避重试，重试三次失败就返回给前端

将结果要写回 Redis
Redis中的Key，添加版本号用于区分 embeding 模型，后缀 id 使用 Md5 算法生成
```
"emb:v1:" + Md5
```
Redis中只能保存 String ，所以需要序列化，设置 TTL
```java
redisTemplate.opsForValue().set(cacheKey, serializeVector(vector), embeddingTtl);
```


## 四、功能

上传文档：

1. 上传到 MinIO
2. 创建文档记录保存到数据库中
3. 异步**提交索引任务**

更新文档：

1. 上传新的文档到 MinIO 存储
2. 修改数据库 doc 的文档记录
3. 异步**提交索引任务**
4. 删除 MinIO的旧文档

重建索引：

1. 修改数据库 doc 的文档记录
2. 异步**提交索引任务**

索引重建前，对数据库文档记录以下内容进行修改：

- 将 doc 所在知识库id、文档名、类型、大小、MinIO路径等
- [有问题]版本号应该在索引管道中更新，将 doc 版本号 + 1（第一次上传时不用）
- 将 doc 的 status 设置为 PENDING
- 将统计字段 ChunkCount、TokenCount、ErrorMsg、IndexAt设置为 null

>这些字段会在重建过程中进行更新



## 五、索引通道

>索引管道负责更新 IndexTask 和 doc 的 status

第一步 ：submit 提交一个索引任务，创建索引任务 IndexTask，插入到数据库表中，将索引任务和用户上下文传递给异步线程池，线程池任务：保存用户上下文，执行索引任务，执行完毕清除用户上下文

第二步：线程池执行索引任务执行

1. 先查询数据库，取文档元数据，得到 MinIO 的 Path，数据库没有直接返回文档不存在，从 MinIO 下载文档，如果遇到网络IO问题，重试提交任务（指数退避）

2. 设置索引任务状态为 RUNNING，文档状态为 PROCESSING

3. 对文档 File 进行解析
4. 对文档进行分块
5. 批量 Embeding

6. ==🟡第六步：数据库文档版本号 + 1==

==🟢第七步：批量创建 chunk 对象，保存为 List，然后分批，批量插入数据库中==

一个文档可能有几百个 chunks，单次插入对数据库压力很大，所以每批 batch = 50 INSERT插入数据库，分批

==🟢第八步：删除旧版本 chunk==

==🟡第九步：更新文档信息：状态DONE、chunks数量、token数量==

第十步：更新任务状态为 DONE
